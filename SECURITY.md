# 安全政策 / Security Policy

## 支持范围

在项目尚未发布版本标签期间，仅支持 `main` 分支的最新提交。出现正式版本后，本文件将明确列出受支持版本。

Until tagged releases exist, only the latest commit on `main` is supported. This file will list supported release lines after versioned releases begin.

## 报告安全问题

请不要在公开 Issue、Pull Request、Discussion、日志或示例文件中披露漏洞、利用步骤、密钥、访问令牌或受保护素材。

1. 优先使用 GitHub 的私密漏洞报告功能（如果仓库已启用）；
2. 如果该入口不可用，请通过 [@LilRayyyy 的 GitHub 主页](https://github.com/LilRayyyy) 联系维护者；
3. 首次联系时只说明受影响组件和影响级别，不要在公开页面粘贴利用细节；
4. 在维护者提供私密沟通渠道后再发送复现材料。

Do not disclose vulnerabilities, exploit steps, secrets, access tokens, or protected source material in public Issues, Pull Requests, Discussions, logs, or examples.

1. Prefer GitHub private vulnerability reporting when it is enabled.
2. If that option is unavailable, contact the maintainer through [@LilRayyyy's GitHub profile](https://github.com/LilRayyyy).
3. In the initial contact, describe only the affected component and impact level; do not paste exploit details on a public page.
4. Send reproduction material only after the maintainer provides a private channel.

## 响应原则

维护者会确认报告、评估影响、协调修复，并在适合时通过 GitHub Security Advisory 发布说明。响应时间取决于问题复杂度和维护者可用性，本项目不承诺固定服务等级。

The maintainer will acknowledge the report, assess impact, coordinate a fix, and publish a GitHub Security Advisory when appropriate. Response time depends on complexity and maintainer availability; this project does not promise a fixed service level.
