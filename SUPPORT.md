# 支持说明 / Support

请选择与问题类型相符的渠道，避免公开敏感源文件、客户演示文稿、密钥或个人信息。

Choose the channel that matches the request. Never publish sensitive source files, customer decks, secrets, or personal data.

## 可复现缺陷 / Reproducible bugs

使用 GitHub 的 Bug Report 表单，提供：

- Codex 或宿主版本与操作系统；
- 输入类型；
- 最小复现步骤；
- 预期与实际行为；
- 已移除敏感信息的日志或示例。

Use the GitHub Bug Report form with the host version, operating system, input type, minimal reproduction, expected and actual behavior, and sanitized logs.

## 功能建议 / Feature requests

使用 Feature Request 表单说明用户问题、使用场景、建议行为、替代方案，以及对视觉保真和语义可编辑性的影响。

Use the Feature Request form to describe the user problem, use case, proposed behavior, alternatives, and expected fidelity/editability impact.

## 使用问题 / Usage questions

在仓库启用 Discussions 之前，可提交普通 Issue，并在标题中注明“使用问题 / Usage”。请先阅读 [README.md](README.md) 和 [`SKILL.md`](skills/ppt-fidelity-editor/SKILL.md)。

Until Discussions is enabled, open a regular Issue with “Usage” in the title. Read [README.en.md](README.en.md) and [`SKILL.md`](skills/ppt-fidelity-editor/SKILL.md) first.

## 安全问题 / Security

安全漏洞必须遵循 [SECURITY.md](SECURITY.md)。不要通过公开 Issue 披露漏洞或利用步骤。

Follow [SECURITY.md](SECURITY.md) for vulnerabilities. Never disclose a vulnerability or exploit steps in a public Issue.

## 不提供的支持 / Unsupported requests

- 获取或破解无权访问的演示文稿或素材；
- 绕过许可证、访问控制或安全限制；
- 为第三方图片生成、PowerPoint 或 Codex 服务提供账户和计费支持；
- 保证特定字体、渲染器或图片模型产生完全一致的结果。

The project does not provide help with unauthorized access, bypassing licenses or controls, third-party account or billing issues, or guarantees of identical output across fonts, renderers, and image models.
